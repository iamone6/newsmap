## 1. 버전 (2026-10-01 기준 최신 안정 버전)

| 구성 요소 | 버전 | 설치 방법 |
|---|---|---|
| PostgreSQL | 18.6 | `postgres:18.6-trixie` (Debian 13) |
| pgvector | 0.8.6 (`0.8.6-1.pgdg13+2`) | PGDG archive apt 저장소. 일반 저장소는 최신 버전만 남기므로 고정 버전을 계속 받을 수 있는 archive를 씀 |

| pg_cron | 사용 안 함 | 스케줄링은 앱 쪽에서 |

## 2. 인프라와 배포

- docker-compose로 띄우고, 지금은 postgres 서비스만 둔다.
- Dockerfile 위치와 이름: `dockerfiles/{fe,be,rag,db}.dockerfile` (지금은 `db.dockerfile`만 있음)
- `.env`는 앱마다 따로 둔다. 저장소에는 `.env.example`만 커밋한다.
  - `apps/db/.env`: `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_DB`. compose가 `env_file`로 읽는다.
  - `apps/be/.env`: Laravel의 `DB_*`
  - `apps/rag/.env`: `DB_*`, `DEEPINFRA_API_KEY`, 임베딩·LLM 모델명. API 키가 소스 코드나 프론트엔드에 노출되지 않게 한다.
- 데이터 저장: 호스트 경로 bind mount `/data/postgres:/var/lib/postgresql` (Ubuntu 호스트, PG18 이미지의 기본 마운트 지점). named volume은 쓰지 않는다.
- 포트: `127.0.0.1:5432`로만 연다 (호스트 내부 접속).
- 스키마: `contracts/schema.sql`을 psql로 직접 적용한다. 마이그레이션 도구는 쓰지 않는다 (백엔드는 Laravel).
- 파티셔닝: PoC 단계라 하지 않는다. 규모는 아직 산정 전이다.
- 보존 기간: 최대 1년, 여유가 되면 늘린다. 기사를 지우면 하위 테이블이 `ON DELETE CASCADE`로 같이 지워진다.
- 시간: 모든 시각 컬럼은 `timestamptz(0)`으로 초 단위까지만 저장한다 (MySQL `DATETIME`처럼 반올림). DB 시간대와 컨테이너 `TZ`는 `Asia/Seoul`.

## 3. 역할 분담

- 수집, 크롤링, LLM 판단, 청킹, 임베딩: Python 워커 (`apps/rag`)
- 조회와 검색: Laravel (`apps/be`)
- cron: 앱 쪽에서 실행하고, DB에는 넣지 않는다.

## 4. 데이터 모델

### 공통
- 기본키는 `id bigint GENERATED BY DEFAULT AS IDENTITY` (Laravel과 호환).
- `created_at`은 수집 시각으로, Laravel의 `created_at`과 같은 의미로 쓴다. RSS의 생성일·수정일은 `rss_created_at`, `rss_updated_at`으로 구분한다.

### 지역: `regions`, `article_regions`
- `regions`: 행정안전부 행정동 코드 마스터 (10자리).
  - 레벨(시도, 시군구, 읍면동), 상위 코드, 이름들을 저장한다.
  - `valid_from` / `valid_to`를 두고, 폐지된 코드도 지우지 않는다.
  - 데이터 적재는 나중에 한다.
- `article_regions`: 기사와 지역의 N:M 관계.
  - 시도·시군구·읍면동 코드를 각각 따로 저장한다 (`regions` FK). 매칭에 실패하면 코드는 NULL로 두고, LLM이 돌려준 원문 이름은 보관한다.
  - 시군구나 읍면동을 판단하기 어려우면 그 단위만 NULL. 지역과 무관한 기사는 행을 만들지 않는다.
  - 여러 지역을 둘 수 있고, 대표 지역은 `is_primary`로 표시한다 (기사당 1개).
  - 기사는 수집 당시의 코드를 그대로 유지한다 (행정동이 개편돼도 바꾸지 않음).

### 기사: `articles`
- 피드와 언론사는 **설정 파일**로 관리한다. DB에는 `feed_key`, `publisher_name`만 저장한다.
- `canonical_url`은 **전역 unique**로 둔다 (같은 기사가 여러 피드에 있어도 1건).
- 제목, 부제목, 본문은 HTML 태그와 특수문자를 제거한 뒤 저장한다.
- `reporters text[]`: 기자 이름만 저장하고 이메일은 저장하지 않는다.
- `published_at`: RSS 발행일 → 없으면 RSS 생성일 → 없으면 수집 시각 순으로 채운다. 어떤 값을 썼는지는 `published_at_source`에 기록한다.
- `rss_updated_at`: 다시 파싱하지 않고 최신값만 갱신한다. 정정·삭제 기사는 반영하지 않는다.
- 원본 HTML은 저장하지 않는다.

### 통신사: `wire_agencies`
- 통신사 이름을 정규화하는 테이블 (정규화 이름 + 별칭 배열).
- `articles.wire_agency_id`: NULL이면 **자사 생산이거나 판단 불가** (둘을 구분하지 않음). 값이 있으면 그 통신사 기사.
- LLM이 찾은 원문 표기는 `wire_source_raw`에 보관한다.

### 이미지: `article_images`
- 순서, URL, 캡션, 출처 원문(`credit_raw`), 라이선스 통신사(`license_agency_id`, NULL이면 자사이거나 표시 없음)를 저장한다.
- 썸네일도 같은 테이블에서 `is_thumbnail`로 표시한다 (기사당 1개).

### 섹션: `sections`, `article_sections`
- 6개 고정 (정치, 경제, 사회, 문화(생활·연예 포함), 스포츠, 과학(IT 포함)). 참조 테이블과 N:M 테이블로 관리한다.
- 여러 개를 둘 수 있지만 되도록 1개만 둔다. 대표 섹션은 `is_primary`로 표시한다 (기사당 1개).

### 대표 값(`is_primary`)의 의미
- 지역과 섹션은 기사 하나에 여러 개 저장할 수 있다. "대표" 표시만 하나로 제한한다.
- 검색 필터에는 대표 여부와 상관없이 모든 지역·섹션이 쓰인다. 대표 값은 지도 마커나 목록 라벨처럼 값이 하나만 필요한 곳에 쓴다.

## 5. 중복 수집 방지
1. `seen_rss_links (feed_key, rss_link)`에 이미 있으면 기사 페이지를 열지 않는다. `updated_at`만 달라졌으면 `rss_updated_at`만 갱신한다.
2. 페이지를 파싱한 뒤 `canonical_url`이 이미 있으면 새 기사를 만들지 않고, 기존 기사 id로 `seen_rss_links`에만 기록한다.

## 6. 처리 상태와 실패
- 처리 상태 추적(status, error, retry)은 하지 않는다.
- LLM 응답 원본과 프롬프트 버전도 저장하지 않는다. LLM 모델은 환경변수로 바꾼다.
- 기사, 지역, 섹션, 이미지, 청크, `seen_rss_links`는 모든 처리가 끝난 뒤 **한 트랜잭션**으로 저장한다. 중간에 실패하면 아무것도 저장되지 않고 다음 cron에서 다시 시도된다.

## 7. 청킹
- Recursive Character Splitter. 문단(줄바꿈)을 우선 기준으로 자른다.
- 토큰 수는 **Qwen3 토크나이저** 기준으로 세고, 청크마다 `token_count`를 저장한다.
- 청크 크기는 **오버랩을 포함해 최대 500 토큰** (본문 약 400 + 앞뒤 각 10% 오버랩).
- 청크 순번(`chunk_index`, 0부터)을 저장한다.
- 원문 `content`와, 임베딩·BM25 검색에 쓰는 `embed_text`를 분리한다. `embed_text`에는 `[지역 | 날짜 | 제목]` 헤더를 붙인다.
- 필터용 비정규화 컬럼:
  - `region_codes`: 상위 지역 코드까지 펼쳐서 저장한다. 하위 지역 필터로는 상위 지역만 판정된 기사가 잡히지 않는다.
  - `section_ids`, `published_at`, `is_wire`

## 8. 임베딩
- DeepInfra `Qwen/Qwen3-Embedding-0.6B` (OpenAI 호환 API)
- 1024차원을 `halfvec(1024)`로 저장한다.
- 모델명과 차원은 환경설정에서 관리하고, 청크별로 모델 정보를 저장하지는 않는다. 사용한 모델은 README에 기록한다.
- 차원을 바꾸면 스키마를 수정하고 전체를 다시 임베딩해야 한다.

## 9. 하이브리드 검색
- 키워드: pg_search BM25, `pdb.lindera(korean)` (KoDic 사전)
- 벡터: HNSW, 코사인 거리 (`m=16`, `ef_construction=64`), `hnsw.iterative_scan = relaxed_order`
- 결합: DB 함수 `search_chunks()`에서 RRF (k=60)로 합친다.
- 필터: 지역 코드, 섹션, 기간, 통신사 제외(`p_exclude_wire`, 기본값 true). 서비스에서 호출할 때마다 값을 넘겨 바꿀 수 있다.

## 10. 남은 확인 사항
- 2026-10-01 로컬 검증 완료: 이미지 빌드, 스키마 적용, 확장 버전(vector 0.8.6, pg_search 0.25.11), 시간대 Asia/Seoul, Lindera 한국어 토큰화, `search_chunks()` 호출(파라미터로 넘긴 `|||`, 필터, 빈 질의, 통신사 제외), 초 단위 반올림, `ON DELETE CASCADE`. 데이터 양이 적어서 인덱스 사용 여부(실행 계획)는 확인하지 않았다.
- 지역·섹션 배열 필터는 pg_search 인덱스 안에서 처리되지 않는다. 그래서 필터를 건 BM25 검색은 상위 N개 최적화를 못 타서 느려질 수 있다 (PoC 규모에서는 허용).
- 행정동 마스터 실제 데이터 적재: 적재 스크립트(`apps/db/scripts/load_regions.py`, KIKcd_H xlsx/CSV 입력, `apps/db/.env`의 `POSTGRES_*`로 접속)는 만들었고, 실제 데이터는 아직 넣지 않았다. `article_regions`의 코드 FK 때문에, 코드까지 저장하려면 수집 전에 먼저 적재해야 한다. 일반구(예: 수원시 영통구)의 `parent_code`는 시(수원시)로 연결하므로, 청크 `region_codes`를 펼칠 때 시 단위도 포함된다.
- 운영 규모를 산정한 뒤 파티셔닝과 HNSW 파라미터를 다시 검토한다.
